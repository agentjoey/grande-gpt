# GrandeGPT Phase 5.5 Closeout

Date: 2026-08-22
Task: `task-p55-20260819-001`
Scope: Reliability hardening before Phase 6

## Objective

Phase 5.5 closes the reliability gaps that were judged too risky to carry into Phase 6: canonical Git consistency, production Gateway restart/activation reliability, and exact-SHA host verification integrity. The phase deliberately does not add a general host execution capability or expand the product boundary.

## Scope completed

### S16 — Canonical Consistency

- Added controlled canonical refresh around the registered repo/default branch.
- Refresh is clean-only and fast-forward-only; dirty or diverged canonical state fails closed.
- `task_open` uses refreshed canonical state rather than silently inheriting stale local main.
- `grande_sync_base` semantics are explicit canonical → task and report `equal / task_ahead / canonical_ahead / diverged` instead of ambiguous `up-to-date` wording.

### S17 — Production Reliability

- Loaded LaunchAgent restart uses `kickstart -k` rather than a destructive bootout-first sequence.
- Unloaded bootstrap has bounded handling for transient bootstrap error 5.
- Restart success is gated on Gateway readiness rather than process-control success alone.
- Runtime activation is observable with `gatewayBuild`, `toolsetEpoch`, `toolsCount`, and `toolsDigest` through status/selfcheck/doctor surfaces.
- Production acceptance completed 10/10 controlled restart rounds with LaunchAgent loaded/running, readiness/MCP recovery, and same-session GrandeGPT probes remaining usable.

### S18 — Verification Integrity

- Added trusted `OuterTestReceipt` state bound to task, repo, exact commit, verification plan, timestamps/result, and host toolchain evidence.
- HEAD or verification-plan changes invalidate stale receipts.
- GrandeGPT self-host merge gate requires current-plan exact-SHA host verification evidence in addition to the existing attestation/CI gates.
- Missing or stale host verification fails closed and returns the bounded host-verification path rather than introducing generic `host_exec` or an unsandboxed profile escape hatch.

- `unit-selfhost`

## Security boundary retained

Phase 5.5 does not add generic shell execution, arbitrary host argv, `host_exec`, or an `unsandboxed: true` candidate-repo profile. Host verification remains constrained by the dedicated verifier/receipt design so candidate repository code does not gain a general escape path into the user host or GrandeGPT control-plane secrets.

## Remaining limitations

- GG-BL-010 remains `MITIGATED`: the observed ChatGPT App/session binding disable behavior has stable operational mitigation and repeated successful regressions, but GrandeGPT cannot prove that every platform-side binding failure mode has been eliminated.
- Other backlog items outside the approved Phase 5.5 scope remain open and are not implicitly promoted into Phase 6.

## Phase 6 readiness

Phase 6 may start only from the merged Phase 5.5 closeout state. New work should preserve the canonical refresh, production activation evidence, and exact-SHA host verification gates established here rather than bypassing them for convenience.
